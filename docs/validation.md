# v0.1.3 AMD 面板与后台恢复验证（2026-11-06）

本轮验收包含 AMD 官方面板的实际状态。通过 CUA 在“音频和视频”中操作总开关及输入下拉框；每次重载后重新取得当前窗口，核对总开关文字“已启用”和输入行的 UGREEN。后台 GET=true 仍须与指定物理麦克风的 AMD 活动采集会话共同满足。

修复了两处恢复缺口：选择“输入设备 → 噪音抑制关闭”会停止输入通道，恢复不能只有 SET；Radeon 在内存中缓存开关和选择，后台恢复后还需要重载其模型。中间版本仅等待重启命令成功和进程替换，本机出现整个音频降噪区域缺失；新版本等待初始化、START、SET 三项新回执，缺失时不报成功。`cncmd restart` 的 `atlogon` 模式可能未初始化 ANR，补发一次隐藏的普通启动请求后，才观察到新初始化回执。随后再次核对实际后台与采集。

共用完成事件也有两种风险：阻塞等待会取走 Radeon 的通知，完全不消费会遗留通知使它读到旧结果。现在仅在命令与专属结果确认完成后，用零超时消费该次通知；面板重载期间不主动发送 AMD 请求。该私有单槽协议仍没有通用的多客户端事务保证。

# v0.1.2 代码复核与验证（2026-11-06）

本轮针对守护失效、成功判断和界面粗糙的反馈，拆出 `engine.rs`，将每个检查周期与 Windows/AMD 调用分开；运行代码和模拟测试使用同一套决策流程。

修复项：

- AMD 出错、离线或版本不支持时，不再跳过 Windows 路由；三个 Windows 输入角色分别处理失败。
- 失败退避限制修复写入，继续观察状态。AMD 虚拟端点反复出现/消失不会清空 AMD 失败退避，原始麦克风重连才重置。
- 暂停/配置更新使旧周期失效，积压命令先合并再检查；等待 AMD 互斥期间可以取消未发送的命令。已提交的单次系统调用仍可能先完成。
- 路由还原读取失败保留原记录；切换目标写入失败时保留旧值和尝试值，防止暂停后失去还原依据。
- 应用路由按 PID、进程创建时间和当前 Windows 会话核对。退出的 PID 不用于还原，移出配置的存活应用会继续被跟踪到还原结束。
- Windows Audio 登录时尚未就绪或枚举失败时保留守护线程，重建枚举器继续尝试。
- Win32 窗口状态用 `RefCell` 限制重入；绘制/销毁等同步消息独立处理，不再在嵌套回调中制造重叠的 Rust 可变引用。
- 重做状态卡片、设置分组、选中导航、字体和留白，保留原生控件和键盘操作。明确显示未保存设置，并为 AMD 与 Windows 分别展示检查依据。
- EXE 版本资源与 Cargo 版本统一为 0.1.2。

# v0.1.1 修复验证（2026-11-06）

用户报告从 AMD 面板关闭降噪后不能恢复。本轮使用 AMD 面板操作、后台 IPC 查询和 Windows 音频会话查询交叉验证。未采集、保存或上传音频内容。

已定位的问题：

- 旧版以 GET=true 即宣布成功，实际 AMD 重新建立物理采集会话存在延迟。
- 关闭 AMD 总开关会退出后台。旧版裸启动 EXE 在关闭配置下直接退出；需要 `NoQuit`。后台存活但返回 -2 时还需要 START_ANS_PROCESS 初始化。
- 修复过程的中间版本在后台异步启动期间立即 SET 设备，后续捕获到 ANRonnxLib.dll 的 0xc0000005 崩溃。AMD 单独启动、随后接回守护只读查询的对照稳定；最终改为启动前写配置、启动后等待，避免重复初始化/设备切换。

| 项目 | 实测结果 |
|---|---|
| AMD 面板关闭输入 | GET=false，物理麦克风上 AMD 会话 inactive |
| 后台恢复输入 | GET=true 先出现，随后 AMD 会话 active；旧版成功提示过早 |
| 安装版设备开关故障注入 | 开关与 AMD 采集会话均恢复，最终包一次约 7.69 秒 |
| 总开关关闭导致后台退出 | 重现旧版启动失败；中间版本又重现 -2 未初始化 |
| 未初始化后台恢复 | 新版发送初始化，重新 GET、复查活动采集后才通知成功 |
| 关闭配置并终止后台 | 最终包回归约 7.19 秒恢复；同一后台随后持续运行超过 45 秒。此前相同时序版本 6.3 秒恢复后持续数分钟未再崩溃 |
| 恢复确认 | 必须同时具备运行开关、指定设备上的 AMD 活动采集会话、配置的路由检查；缺少会话时不累计成功 |
| 原生 UI | v0.1.1 显示新验证依据与 AMD 面板显示限制，恢复事件和计数可见 |
| 格式、Clippy、单元测试 | 通过；新增开关开启但采集未启动时不准报成功的回归测试 |

**未解决的显示差异**：后台与 Windows 会话恢复后，AMD 设置面板仍可显示“噪音抑制关闭”。切换页面、关闭重开面板及重启 RadeonSoftware 进程均未解决。本版本没有实现面板状态同步，也未验证音频降噪效果。不要据后台采集状态宣称 AMD 面板验证通过。

**仍未验证**：物理 USB 拔插、Windows 重启登录、YY/KOOK 实际通话、其他 AMD 版本、长时间稳定性和算法效果。YY/KOOK 内部配置守护尚未实现。
