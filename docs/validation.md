# v0.1.1 修复验证（2026-11-06）

用户报告从 AMD 面板关闭降噪后不能恢复。本轮使用 AMD 面板操作、后台 IPC 查询和 Windows 音频会话查询交叉验证。未采集、保存或上传音频内容。

已定位的问题：

- 旧版以 GET=true 即宣布成功，实际 AMD 重新建立物理采集会话存在延迟。
- 关闭 AMD 总开关会退出后台。旧版裸启动 EXE 在关闭配置下直接退出；需要 `NoQuit`。后台存活但返回 -2 时还需要 START_ANS_PROCESS 初始化。
- 修复过程的中间版本在后台异步启动期间立即 SET 设备，后续捕获到 ANRonnxLib.dll 的 0xc0000005 崩溃。AMD 单独启动、随后接回守护只读查询的对照稳定；最终改为启动前写配置、启动后等待，避免重复初始化/设备切换。

| 项目 | 实测结果 |
|---|---|
| AMD 面板关闭输入 | GET=false，物理麦克风上 AMD 会话 inactive |
| 后台恢复输入 | GET=true 先出现，随后 AMD 会话 active；旧版成功提示过早 |
| 安装版设备开关故障注入 | 开关与 AMD 采集会话均恢复，最终包一次约 7.69 秒 |
| 总开关关闭导致后台退出 | 重现旧版启动失败；中间版本又重现 -2 未初始化 |
| 未初始化后台恢复 | 新版发送初始化，重新 GET、复查活动采集后才通知成功 |
| 关闭配置并终止后台 | 最终包回归约 7.19 秒恢复；同一后台随后持续运行超过 45 秒。此前相同时序版本 6.3 秒恢复后持续数分钟未再崩溃 |
| 恢复确认 | 必须同时具备运行开关、指定设备上的 AMD 活动采集会话、配置的路由检查；缺少会话时不累计成功 |
| 原生 UI | v0.1.1 显示新验证依据与 AMD 面板显示限制，恢复事件和计数可见 |
| 格式、Clippy、单元测试 | 通过；新增开关开启但采集未启动时不准报成功的回归测试 |

**未解决的显示差异**：后台与 Windows 会话恢复后，AMD 设置面板仍可显示“噪音抑制关闭”。切换页面、关闭重开面板及重启 RadeonSoftware 进程均未解决。本版本没有实现面板状态同步，也未验证音频降噪效果。不要据后台采集状态宣称 AMD 面板验证通过。

**仍未验证**：物理 USB 拔插、Windows 重启登录、YY/KOOK 实际通话、其他 AMD 版本、长时间稳定性和算法效果。YY/KOOK 内部配置守护尚未实现。

# v0.1.0 历史验证（仅后台开关，不足以证明采集恢复）

验证环境：Windows x64，已安装且通过 SHA-256 校验的 AMD Noise Suppression 后台；UGREEN CM564 原始输入、AMD Streaming 虚拟输入，同时存在网易远程虚拟音频设备。测试未采集或上传音频。

| 项目 | 结果 |
|---|---|
| Rust fmt / Clippy all-targets，warnings 为错误 | 通过 |
| 配置序列化、未知字段拒绝、间隔与输入回路校验 | 通过 |
| 退避时序、最大退避、重连重置 | 通过 |
| AMD 后台只读 GET | 返回 0，运行开关 true |
| 真实故障注入 | SET false，GET 验证 false；AudioPin 自动恢复；GET 验证 true |
| 最终安装包恢复耗时 | 一次约 3.89 秒（包含 AMD 切换耗时；不是 SLA） |
| 恢复后复查与界面计数 | “正在守护”，自动恢复 1 次，日志记录关闭与恢复 |
| AMD 虚拟设备短暂离线后恢复 | 故障注入中观察到，等待重连后返回正常 |
| Windows 默认设备 API | 三角色幂等写入、读取复查通过 |
| Windows 应用输入偏好 API | 自身测试 PID 的三角色偏好写入、同一偏好读回、还原通过；未验证实际采集设备 |
| 五页 UI、配置保存 | CUA 实际检查通过 |
| 单实例 | 第二次启动打开已有窗口，无重复守护 |
| 安装及自启 | 用户目录安装、开始菜单快捷方式、HKCU Run 项验证通过 |
| 运行库依赖 | PE imports 仅 Windows 系统 DLL，MSVC CRT 静态链接 |
| 资源占用样本 | 工作集约 19.43 MiB，私有内存约 3.25 MiB，15.03 秒耗 CPU 0.0781 秒（窗口可见） |

后台事件为共用自动复位事件。初始测试暴露了与 Radeon Software 的响应竞用；实现已改为命令专属响应字段确认、AudioPin 本身命名互斥、请求超时退避，并在后续读到实际开启后记录恢复。

没有做的验证：物理拔插 USB、Windows 重启登录、YY/KOOK 实际通话、不同 AMD 驱动版本、算法降噪效果。应用偏好测试只验证 Windows 系统设置的读写，测试进程没有建立录音流；因此不能证明音频实际经过指定设备。YY/KOOK 内部配置守护尚未实现，兼容效果未验证。
